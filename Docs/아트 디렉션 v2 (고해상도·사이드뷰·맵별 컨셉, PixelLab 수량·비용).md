## 1. 문제 정의 — 왜 픽셀이 커 보이는가

현행 수치: 타일 16px, PPU 16, `MapWorld.cs`의 `orthographicSize = 5f`.

- 화면 세로 = 5 × 2 = 10유닛 = **세로 10타일 = 160 아트픽셀**.
- 1080p 모니터에서 아트 1픽셀이 화면 1080 ÷ 160 = **6.75픽셀로 확대**된다. 비정수 배율이라 픽셀 뭉개짐/지터도 생긴다.
- 게임보이급(160px 세로) 밀도를 풀HD에 뿌리는 셈 — "저해상도처럼 보인다"는 불만의 수치적 원인.

## 2. 해상도 체계 결정 (v2)

**결정: 타일 32px · 캐릭터 64px 캔버스 · PPU 32 · 가상 해상도 640×360 (1080p에서 정수 3배).**

| 항목 | v1 (현행) | **v2 (결정)** | 근거 |
|---|---|---|---|
| 발판 타일 | 16px | **32×32px** | PixelLab 사이드스크롤러 타일셋 최대치가 32. 모던 도트 사이드뷰 표준(32px 타일급) |
| 캐릭터 캔버스 | 24px (본체 16) | **64×64px (본체 높이 48~52px ≈ 1.5타일)** | standard 모드 1회 생성 범위 내. 사이드뷰 캐릭터 표준 감각(48~64px) |
| 소품 | 32px | 32~128px (아래 목록별 명시) | Tier1 상한 320×320 내 |
| 배경 레이어 | 없음 | 레이어당 **320×180** 가로 심리스 스트립 | Tier1 해상도 상한. 가로 반복(loop-x)로 폭 확장 |
| PPU | 16 | **32** (1타일 = 1유닛 유지) | 코드의 유닛 단위 로직 보존 |
| 카메라 | orthoSize 5 | **orthographicSize 5.625** + URP 2D Pixel Perfect (assetsPPU 32, refRes 640×360) | 아래 계산 |

### 카메라 계산 — 불만 해소 근거

- orthoSize 5.625 → 세로 11.25유닛 = **세로 11.25타일 = 360 아트픽셀**.
- 1080p: 1 아트픽셀 = 정수 **3픽셀** (720p=2, 1440p=4, 4K=6 — 전부 정수배, 왜곡 없음).
- 화면 픽셀 밀도 v1 대비 **2.25배** (160 → 360), 타일당 디테일 **4배** (16² → 32²).
- 가로 시야 20타일(640px) — 사이드뷰 탐색에 충분한 시야. 캐릭터는 화면 세로의 약 1/6로 메이플 필드 감각에 근접.
- 적용 지점: `MapWorld.cs:78`의 `orthographicSize = 5f` → 5.625 + Pixel Perfect Camera 컴포넌트. 퍼즐 보드 화면(`GameApp.cs:346`)은 TMP 텍스트 기반이라 이번 개편 대상 아님.

## 3. 공통 스타일 가이드 — "같은 세계"를 만드는 규칙

메이플 엘리니아 권역처럼 **문법은 공유, 변주는 팔레트·소품**으로 낸다. 수묵·한지 제안 톤 유지(컨셉 확정 전 제안 취급).

1. **아웃라인**: 전 에셋 공통 먹색 계열 1px(#2B241D 근사). 순수 검정 금지.
2. **셰이딩**: 셀 2단(기본색+음영 1단) + 하이라이트 1단. 디더링은 배경 원경에만 허용.
3. **채도 대역**: 지형·건물 30~55%, 액센트(등불·단청·깃발) 60~75%. 형광 금지.
4. **하늘 시스템**: 전 지역 공통 그라데이션 구조(상단 진함 → 지평선 밝음), 지역별로 시간대·색만 변경. 원경에 먹 번짐 실루엣 산세 공통 사용.
5. **지형 문법**: 표면(풀/기와/돌) + 몸체(흙/석축) 2층 구조를 전 지역 동일하게 — PixelLab 사이드스크롤러 타일셋의 surface/base 구조와 일치.
6. **글자 모티프**: 미회수 자음 영향권은 먹 얼룩·균열 오버레이(로컬 후처리, 생성 0회)로 통일.
7. **접근성**: 스팟 상태(열림/클리어/다음/잠김)는 색+형태(문양·아이콘) 이중 코딩 유지.
8. **PixelLab 프롬프트 공통 접두**: "Korean Joseon dynasty folk style, ink-wash inspired muted palette, dark sepia outline, side view platformer" + 지역 키워드.

### 4-3. 받침 고개 (map_03, 받침 글자)

3. **2단계 — 캐릭터 완성 (약 90회)**: jump/climb/interact 애니. 사이드뷰 이동 코드와 함께 검수.
4. **3단계 — 지역 확장 4개 (약 88회)**: 마을 → 고개 → 사찰 → 저잣거리 순(스토리 진행순). 지역당 22회, base tile 체인으로 지형 연속성 유지(manifest의 체인 생성 방식 재사용).
