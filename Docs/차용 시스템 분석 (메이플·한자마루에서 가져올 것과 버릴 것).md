# 차용 시스템 분석 — 메이플스토리 · 한자마루에서 가져올 것과 버릴 것

2026-07-17 작성. 사용자가 확정한 3축(**급수 = 자음 사다리 승급 / 도감 = 수집 학습장 / 전투 = 글자 만들기 리듬**)을 출발점으로, 두 게임에서 무엇을 왜 차용하고 무엇을 버릴지 판단하는 문서.

관련 문서: `게임기획초안` 13~15·20·24장, `스토리기획` 3~4.5장, `사이드뷰 전환 기획` 전체, `구현결정로그` D-19/22/23.

## 0. 결론 요약

| 축 | 현재 상태 | 판단 | 최소 작업 |
|---|---|---|---|
| 급수 | **이미 있음** (`RecoveredConsonants`, D-22 게이트, D-23 방 보상) | 시스템 추가 불요. **시각화만 없음** | 자음 사다리 진열 11칸 + 회수 시 ▒ 복원 연출 |
| 도감 | **이미 있음** (`GlyphCodexPanel` — 만든 글자 나열) | 구조 결함: **목표가 없어 수집 동기 0** | 나열 → **반절표 격자**로 개편 + 등록 연출 |
| 전투 | **이미 있음** (`BattleState` — 공격/수비/기술 + 시련) | 축이 어긋남: 무기 수치로도 이길 수 있음 | 수치 조정으로 "퍼즐로만 이긴다" 복원 (개편은 나중) |

**이 문서의 가장 중요한 문장**: 세 축 모두 **새로 만들 게 아니라 이미 있는 걸 보이게 하는 일**이다. 신규 시스템 제안은 이 문서에 없다. 그리고 한자마루의 구조는 대부분 **이식 불가**다 — 이유는 1장.

## 1. 대전제 — 한자마루를 벤치마크로 삼을 때의 최대 함정

한자마루가 MMO가 될 수 있었던 이유는 게임 설계가 뛰어나서가 아니라 **한자가 암기 대상이었기 때문**이다.

| | 한자 | 한글 |
|---|---|---|
| 학습 대상 | 개별 글자 수천 자의 **음·훈·획순** | 자모 24개 + **조합 규칙** |
| 학습 방식 | 반복 암기 (5급 준비에 5,000회 반복 — 개발사 자체 설명) | 이해 (한 번 알면 끝) |
| 학습량의 성질 | **무한에 가까운 물량** | **30분이면 바닥남** |
| 게임 구조와의 궁합 | 반복 = 그라인딩 = **MMO 레벨링과 완벽히 일치** | 반복할 게 없음 → **MMO 구조를 붙일 이유가 없음** |

한자마루는 "5,000번 반복해야 하는 숙제"를 "5,000마리 잡는 사냥"으로 바꿨다. 이 치환이 성립한 건 양쪽 다 반복이라서다. 우리는 그 전제가 없다.

**따라서**:
- 한글 학습량으로 콘텐츠 분량을 채우려는 순간 게임이 죽는다. 30분이면 다 가르치고 나면 남는 게 없기 때문이다.
- 우리 게임의 콘텐츠 분량은 **학습량이 아니라 퍼즐 설계량**에서 나와야 한다. (= 기획초안 24장 결론과 동일)
- 한자마루에서 가져올 수 있는 건 **레벨링·던전·급수 구조가 아니라, "학습 대상을 게임 오브젝트 자체로 만든" 단 하나의 발명**뿐이다 (2.1장).

> 냉정하게: 한자마루는 우리의 참고 대상이라기보다 **경고 사례**에 가깝다. 유사점은 "한국어 문자 + 횡스크롤"이라는 표면뿐이고, 경제·학습·콘텐츠 구조는 전부 다르다.

## 2. 한자마루 분석

사실 관계 (검증됨): 에듀플로 개발 / NHN 서비스 2009.4.1 출시 → 나우콤 이관 → **2012.9.10 서비스 종료**. 2D 횡스크롤 MORPG, 메이플스토리와 외형·조작이 유사. 종료 사유는 게임성 붕괴가 아니라 **캐시 아이템이 팔리지 않아 수익이 나지 않은 것**.

### 2.1 실제로 작동한 것 — "획 = HP 바" (유일하게 위대한 부분)

- 몬스터 몸통에 한자가 새겨져 있고, **때릴 때마다 획순대로 획이 하나씩 지워진다.** 다 지우면 몬스터가 죽는다.
- 타격마다 훈음이 소리로 나오고, **막타에 뜻이 공개**된다.
- 즉 HP 바가 곧 학습 대상이었다. **퀴즈 창이 뜨지 않는다.** 플레이어는 "공부한다"고 느끼지 않고 그냥 때리는데, 시선이 가장 오래 머무는 곳(몬스터)에 학습 대상이 얹혀 있어서 학습이 부산물로 발생했다.

**왜 이게 작동했나**: 학습과 게임이 **같은 오브젝트, 같은 동사, 같은 피드백 루프**를 공유했다. 분리된 순간이 0이었다.

**우리에게 주는 함의 — 그런데 우리는 이미 이걸 가지고 있다.**
우리 퍼즐 보드는 "학습 대상(자모)"이 곧 "게임 오브젝트(타일)"이고, "학습 행위(조합 원리)"가 곧 "게임 동사(밀기)"다. 한자마루가 발명한 그 하나를, 우리는 게임 전체의 코어로 이미 쓰고 있다. **한자마루보다 나은 위치에서 시작한다.**
→ 그래서 이 축에서 추가로 차용할 것은 없다. **지킬 것**만 있다: *퍼즐 밖에 학습 UI를 만들지 마라.*

### 2.2 실패한 것 — 게임 바깥에 붙인 학습 장치 전부

한자마루는 위 코어 밖에 이런 것들을 덧붙였다:

| 장치 | 성격 | 결과 |
|---|---|---|
| 학습지(교재) 동봉 | 게임 밖 | 숙제 |
| 복습 던전 (진행도 100% 던전 재방문 = 복습 의도) | 게임 안이지만 목적이 학습 | **의도만 학습, 체감은 노가다** |
| 실전 모의고사 | 게임 밖 | 완벽한 숙제 |
| 급수 승급 시험 (급수 최종던전 '마신' 사냥) | 게임 안 | 이건 성공한 축 — 시험을 **보스전으로 치환**했기 때문 |
| 연재만화 | 부가물 | 무해하나 무관 |

**"학습과 게임이 분리되면 왜 재미없어지는가"** — 한자마루가 증명한 메커니즘:

1. **동기의 출처가 바뀐다.** 코어 루프(사냥)의 동기는 "내가 하고 싶어서"다. 모의고사의 동기는 "해야 해서"다. 두 개를 한 게임에 넣으면 플레이어는 **후자를 전자의 대가(代價)로 인식**한다. 즉 게임이 "숙제 하면 놀게 해주는 장치"가 된다.
2. **결제자와 플레이어가 분리된다.** 학습 장치가 두꺼울수록 부모에게 팔린다. 부모가 사고 아이가 한다. 아이는 "부모가 시킨 것"으로 인식하고 **자발적 지출을 하지 않는다** → 캐시가 안 팔린다 → 2012년 종료. **이 게임은 게임성이 나빠서 망한 게 아니라, 교육 상품으로 포지셔닝된 대가로 망했다.**
3. **복습 던전의 교훈이 가장 뼈아프다.** 겉보기엔 게임 안에 있었지만(던전이니까), 재방문의 **보상이 학습이었다**. 플레이어에게 "이미 다 아는 걸 또 하라"는 요구는 게임 문법상 그냥 그라인딩이다. **의도가 교육이면 게임 안에 있어도 숙제가 된다.** 학습 장치는 위치가 아니라 **보상 구조**로 판별된다.

### 2.3 우리가 피해야 할 함정 (체크리스트)

- [ ] **퍼즐 밖에 "학습 UI"를 만들지 않는다.** 뜻풀이 창, 발음 강의, 단어장, 복습 모드, 실력 테스트 — 전부 금지.
- [ ] **도감에 교과서를 넣지 않는다.** 도감은 *내가 만든 것의 전시*지 *배워야 할 것의 목록*이 아니다 (4.2장에서 상술).
- [ ] **"이미 아는 것을 반복시키는" 보상을 만들지 않는다.** 복습 던전 = 재플레이 파밍. 우리는 D-19에서 이미 골드 재클리어 파밍을 막아뒀다 — 이 원칙을 다른 시스템에도 유지.
- [ ] **교육 상품으로 포지셔닝하지 않는다.** 스토어 페이지·트레일러에 "학습", "교육", "배우는"을 앞세우는 순간 한자마루의 경제 구조로 걸어 들어간다. 기획초안 22장 "교육게임처럼 보이면 매력이 줄어든다"의 구체적 근거가 이것이다.
- [ ] **급수를 숫자·시험으로 표현하지 않는다.** 한자마루의 급수는 한자능력검정시험 급수 체계를 그대로 가져와서 성공했지만(외부 공인 자격이라는 실물 보상이 있었으므로), 우리에겐 대응하는 외부 자격이 없다. 숫자 급수만 흉내내면 **보상 없는 시험 냄새**만 남는다.

## 3. 메이플스토리 분석 — 1인 퍼즐 게임 규모로 선별

메이플은 우리가 물량으로 절대 흉내낼 수 없는 게임이다. 그러니 "무엇이 좋았나"가 아니라 **"물량 없이도 복제 가능한 것만"** 골라야 한다.

### 3.1 가져올 것

| 요소 | 왜 좋은가 | 우리 상태 |
|---|---|---|
| **이동감** — 즉시 최고속(가감속 없음), 공중 제어 100%, 원웨이 발판, 낙사·낙뎀 없음 | 이동 자체가 마찰이 아니라 **간식**이 된다. 목적 없이 점프하며 다녀도 기분이 좋다 | **이미 채택 완료** (사이드뷰 기획 1장). 추가 작업 없음 |
| **허브 문법** — 마을에 상점·출구·다음 목적지가 다 모임 | 미니맵 없이도 "여기서 뭘 하지"가 해결됨 | **이미 채택** (시작의 마을 3단 테라스, 사이드뷰 7.2장) |
| **비언어 어포던스** — 느낌표·화살표·색만으로 상태 전달 | 텍스트 0줄로 외국인 대응 | **이미 채택** (↑ 아이콘, 스팟 상태색, ▒) |
| **수직으로 읽히는 진행** — 위로 갈수록 후반 콘텐츠 | 성장이 **공간으로** 읽힘. UI가 필요 없음 | **이미 채택** (마을 required가 높을수록 위층) |
| **한 장면의 밀도** (엘리니아 첫인상) | 1인이 못 이기는 건 맵 개수지 **한 컷의 밀도**가 아니다. 5맵뿐이니 각 맵 **첫 진입 화면 1컷**에 아트 자원을 몰아주면 물량 열세를 상쇄 | **미반영 — 아트 문서에 요구사항으로 전달할 것** |

> 5개 중 4개가 이미 반영돼 있다. 즉 메이플 차용은 사실상 끝났고, 남은 건 아트 쪽 요구사항 1건뿐이다.

### 3.2 안 가져올 것 (메이플의 본체 = 우리에게 독)

| 요소 | 왜 독인가 |
|---|---|
| **레벨·경험치** | 시간 투자로 오르는 축. 퍼즐 게임에 이걸 넣으면 "막히면 레벨 올려서 뚫는" 경로가 생긴다 = **퍼즐의 패배**. 우리는 별(효율)·자음(진행)이 이미 성장 축이고, 둘 다 시간이 아니라 **이해**를 요구한다 |
| **필드 몬스터·리스폰·그라인딩** | 1장의 결론대로 우리는 반복시킬 학습량이 없다. 사이드뷰 기획 12장에서 이미 비범위로 확정 — **유지** |
| **랜덤 드롭·확률 강화·큐브** | 확률로 시간을 태우는 장치. 유료 싱글 게임에 넣을 이유가 0 |
| **캐시샵** | 한자마루를 죽인 바로 그것. 우리는 유료 패키지 — 애초에 무관 |
| **소셜(길드·파티·거래)** | 서버 비용 + 1인 운영 불가 |
| **일일 퀘스트·출석 보상** | 리텐션 훅은 F2P 장치다. 유료 싱글에선 **무의미하고 해롭다** (플레이어를 붙잡을 게 아니라 놓아줘야 리뷰가 좋다) |
| **레벨 게이팅 맵** | 우리 자음 게이트(D-22)가 상위 호환이다. 레벨 게이트는 "시간을 더 써라", 자음 게이트는 "저길 먼저 가라" — 후자는 **길잡이**고 전자는 **벽**이다 |
| **무한 확장 콘텐츠** | 1인. 5맵을 끝내는 게 목표 |

## 4. 3축 번안 설계

### 4.1 급수 = 자음 사다리 승급

**한자마루에서 가져올 단 하나**: 급수가 **레벨과 별개 축**이었다는 것. 레벨은 시간이 올려주지만 급수는 **최종던전 마신을 잡아야만** 올랐다. 즉 *시간의 축*과 *증명의 축*을 분리했다.

**우리 대응 — 이미 완비돼 있다**:

| 한자마루 | 우리 | 상태 |
|---|---|---|
| 급수 (8급→1급) | 자음 회수 11단 (ㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ, D-23) | 구현됨 |
| 급수별 콘텐츠 제한 | 자음 게이트 ▒ (D-22) | 구현됨 |
| 승급 시험 = 마신 던전 | 사천왕 보스전 | 구현됨 |
| 급수증·칭호 (캐릭터에 붙어다님) | **없음** | ← 유일한 공백 |

**따라서 할 일은 시스템 추가가 아니라 두 가지 시각화뿐이다.**

**① 자음 사다리 진열 (11칸 + 시작 3칸)**
- 위치: 도감 패널 좌측 열 = 반절표의 행 머리와 통합 (4.4장).
- 표시: `ㄱㄴㄷ`(시작, 회색 각인) / 회수한 자음(금색 + 어디서 되찾았는지 1줄) / 미회수(▒ 실루엣).
- 값: 기존 `ProgressStore.RecoveredConsonants` 읽기만 함. **신규 데이터 0.**
- 목적: "얼마나 왔고 얼마나 남았나"를 한 화면에. 현재는 이게 어디에도 없다.

**② 승급 연출 = 세상이 복원되는 순간 (핵심)**
- 현재: 방 클리어 → 맵 복귀 → 자음 회수 **팝업 1개**. 11번의 승급이 전부 같은 팝업.
- 개선: 팝업 대신(또는 팝업 직후) **화면에 보이는 ▒들이 순차적으로 진짜 글자로 복원되는 애니메이션**. `BrokenText`가 이미 있으므로 트리거만 붙이면 된다.
  - 타이밍: 자음 회수 확정 → 0.3초 정적 → 맵 간판·출구 표지·상점 간판의 해당 자음 포함 글자가 좌→우로 0.08초 간격 복원 → 회수 자음이 사다리에 각인되는 소리.
  - 총 길이 **1.2초 이내**. 스킵 가능.
- 왜 이게 급수의 올바른 번안인가: 한자마루의 급수 보상은 *숫자가 올라감*이었다. 우리 보상은 ***세상이 읽히기 시작함***이다. 후자가 압도적으로 강하고, 우리에게만 가능하며, **텍스트 0줄로 외국인에게도 통한다.**

**하지 말 것**: 숫자 급수(1급~8급) 병기, 급수 시험 문제 풀이, 급수별 칭호 텍스트 나열.

### 4.2 도감 = 수집 학습장 → **반절표(反切表)로 재설계**

**현재 `GlyphCodexPanel`의 구조적 결함**: 만든 글자를 격자에 나열하고 개수만 표시한다. → **목표가 없다.** 수집물은 "빈 칸이 보여야" 채우고 싶어진다 (메이플 몬스터북의 실루엣 문법). 지금 도감은 채울 빈 칸이 존재하지 않으므로 **수집 동기가 구조적으로 0**이다.

**그런데 전체 집합을 정의할 수 없다**: 한글 완성형은 11,172자. 달성률 100%는 불가능하고 무의미하다. → 이게 지금 도감이 나열형인 이유이자, 그냥 격자를 늘려선 해결되지 않는 이유다.

**해법: 반절표.** 세로축 = 자음, 가로축 = 기본 모음 10종.

```
        ㅏ  ㅑ  ㅓ  ㅕ  ㅗ  ㅛ  ㅜ  ㅠ  ㅡ  ㅣ
  ㄱ    가  갸  거  겨  고  교  구  규  그  기      ← 시작부터 열림
  ㄴ    나  냐  너  녀  노  뇨  누  뉴  느  니
  ㄷ    다  댜  더  뎌  도  됴  두  듀  드  디
 ─────────────────────────────────────────
  ㄹ    ▒   ▒   ▒   ▒   ▒   ▒   ▒   ▒   ▒   ▒     ← 자음 회수 시 행이 열린다
  ㅁ    ·   ·   ·   ·   ·   ·   ·   ·   ·   ·
  ...                                              ← 14행 × 10열 = 140칸
```

- **시작 3행 30칸 → 최종 14행 140칸.** 자음을 되찾을 때마다 **행이 하나씩 열린다** = 도감이 자음 사다리와 직접 물린다 (사용자 방향 "획득한 자음은 특별 파트로"의 구현체).
- 미제작 = 흐린 실루엣(글자가 흐리게 보임 — 명세 8장 진행도 판의 흐린 목표 표시와 동일 문법). 미회수 자음 행 = ▒.
- 제작 = 불이 들어옴. `RegisterGlyph`가 이미 있으므로 데이터는 그대로.
- **달성률이 성립한다**: "ㄱ 서가 7/10", 전체 "48/140". 100%가 **가능한 숫자**가 됐다.
- **특별 서가** (본표 밖, 별도 탭): 받침글자 / 복합모음 글자 / 쌍자음·겹받침 글자. 여긴 상한 없는 **나열형 유지** (현재 도감 그대로 + `IsRare` 금색 판정 재사용). 본표 = 달성, 특별 서가 = 발견.

**왜 반절표인가 (이 문서에서 가장 강한 아이디어)**:
1. **실물 역사 유물**이다. 조선 시대 한글 학습판. 세계관과 100% 맞는다 — 도감 아이콘이 곧 훈민정음 소품이 된다.
2. **표 자체가 한글의 구조를 설명한다.** 가로축 모음 × 세로축 자음이라는 격자를 보는 순간, 한국어를 몰라도 "이 문자는 조합이구나"가 **한 장에 읽힌다.**
3. 그런데 이걸 **교재로 주는 게 아니라 내가 만든 글자로 채워지는 수집 격자로 준다.** → 학습 UI가 아니라 수집 UI다. **2.3장 함정을 정면으로 피하면서 학습 효과는 최대**. "퍼즐의 재미가 먼저, 학습은 부산물"의 교과서적 구현.
4. 외국인 한글 교재의 첫 페이지가 정확히 이 표다. 우리는 같은 것을 **숙제가 아니라 트로피 케이스**로 준다.

**수집 연출 (사용자 방향 "수집 연출 강화")**:
- 최초 등록 시: 보드의 글자 타일 → **도감 아이콘으로 날아가는 0.4초 비행** + 각인음 + 도감 아이콘 1회 반짝임. 희귀(`IsRare`)면 금색 궤적 + 다른 소리.
- 스테이지 클리어 팝업에 "새로 등록된 글자 N개" 줄 추가 (이미 있는 팝업에 한 줄).
- **이게 수집 쾌감의 90%다.** 도감을 아무리 예쁘게 만들어도 등록 순간에 아무 일도 안 일어나면 죽은 시스템이다.

**하지 말 것**: 뜻풀이·예문·발음 강의·품사 표시. 뜻은 **게임에 실제로 나온 단어에 한해** 자동으로 1줄 붙는 정도가 상한. 그 이상은 즉시 학습지가 된다.

### 4.3 전투 = 글자 만들기 리듬

**한자마루의 발명 재확인**: 한자의 **획이 곧 HP 바**였다. 별도 퀴즈 창이 없었다.

**현재 `BattleState`의 문제 (냉정하게)**:
- 흐름: 플레이어가 **공격/수비/기술** 선택 → 데미지 → 몬스터가 **시련(퍼즐)** 제시 → 판정.
- 즉 **RPG 턴 메뉴**와 **퍼즐 창**이 별개 게임으로 병존한다. 이건 한자마루의 좋은 절반(획=HP)이 아니라 **나쁜 절반(분리된 학습 파트)의 구조**를 닮았다.
- 구체적 위험: `Act(Attack)`는 **퍼즐과 무관하게 `PlayerAtk - Config.def` 데미지를 넣는다.** `PlayerAtk = 3 + 무기 공격력`. 즉 **상점에서 골드를 태워 무기를 사면 퍼즐 실력과 무관하게 보스를 깎을 수 있다.** 장비 인플레이션이 조금만 생기면 "퍼즐 게임의 보스전을 쇼핑으로 통과"하는 경로가 열린다. 3.2장에서 메이플의 레벨을 거부한 논리와 정확히 같은 이유로 이건 막아야 한다.

**올바른 번안 (목표 형태)**: **보스 HP = 글자다.**
- 보스 초상 위에 그가 삼킨 글자 3~5개가 ▒로 떠 있다.
- 퍼즐 보드에서 글자를 하나 만들어 수집할 때마다 ▒ 하나가 복원되며 보스가 그만큼 깎인다.
- **HP 숫자가 아니라 남은 글자 수가 HP다.** 한자마루의 "획이 지워진다"에 정확히 대응하는 한글판이고, 우리 세계관(대마왕이 글자를 삼켰다)과 문자 그대로 일치한다.
- 공격/수비/기술 메뉴는 → **퍼즐 파라미터를 바꾸는 행동만 남긴다.** (수비 = 다음 시련 여유 +2수 ← 이미 그렇게 구현돼 있다. 이건 좋은 설계다.) 순수 데미지 딜링은 삭제.

**그런데 지금 하지 않는다.** `BattleState`는 이미 구현·테스트(`BattleStateTests.cs`)까지 끝났고, 위 개편은 전투 화면·설정 JSON·테스트를 전부 갈아엎는 큰 작업이다. 완성도 초기 단계에서 지불할 값이 아니다.

**대신 지금 할 것 — 수치 조정 한 줄 수준으로 축만 되돌린다**:

| 항목 | 현재 | 조정안 | 이유 |
|---|---|---|---|
| `Act(Attack)` 데미지 | `PlayerAtk - def` (무기 비례) | **1 고정** (또는 삭제하고 "노려보기"로 리네이밍) | 쇼핑으로 이기는 경로 차단 |
| 카운터(시련 성공) 데미지 | `PlayerAtk - def` | **유지 또는 상향** | 승리의 주 경로 = 퍼즐 |
| 무기 공격력의 역할 | 딜량 | **카운터 데미지에만 기여** | 장비는 퍼즐 성공을 *증폭*할 뿐, *대체*하지 못함 |

→ 결과: **퍼즐을 못 풀면 절대 못 이긴다. 장비는 잘 푸는 사람을 빠르게 해줄 뿐.** 이게 최소 비용으로 지킬 수 있는 축이다.

**"리듬"의 정의 (오해 방지)**: 박자 입력 게임이 아니라 **템포**다.
- 시련 1회 = **3~8수** 규모 퍼즐 (일반 스테이지보다 작게 — 전투 중이니까).
- 전투 1회 = **시련 3~5회**, 총 **2~3분**.
- **실시간 타이머 절대 금지.** 퍼즐 게임에 시간 압박을 넣으면 "생각하는 재미"를 죽인다. 제한은 오직 **수**로만 (현재 `moveLimit` — 올바르다).
- 전조 시스템(다음 시련의 제한 수 미리 공개)은 이미 구현돼 있고 이 템포의 핵심이다. **유지.**

### 4.4 세 축이 만나는 지점 — UI 하나로 수렴한다

이 문서의 설계가 옳다면, 세 축은 **같은 화면**에서 만나야 한다:

```
┌─ 훈민정음 반절표 ────────────────────────────┐
│        ㅏ ㅑ ㅓ ㅕ ㅗ ㅛ ㅜ ㅠ ㅡ ㅣ    48/140 │
│  ㄱ ●  가 갸 거 겨 고 교 구 규 그 기         │  ← 도감 (4.2)
│  ㄴ ●  나 냐 너 녀 노 뇨 누 뉴 느 니         │
│  ㄷ ●  다 댜 더 뎌 도 됴 두 듀 드 디         │
│  ㄹ ◆  라 랴 ·  ·  로 ·  ·  ·  르 리        │  ← ◆ = 증표(사천왕 격파)
│  ㅁ ▒  ▒ ▒ ▒ ▒ ▒ ▒ ▒ ▒ ▒ ▒               │  ← 급수 사다리 (4.1)
│  ...                                          │
│  [본표]  [특별 서가]                          │
└───────────────────────────────────────────────┘
```

- **행 머리 = 자음 사다리** (급수 축) → 회수 상태 표시
- **행 내용 = 도감** (수집 축) → 만든 글자 점등
- **행 머리의 증표(◆) = 사천왕 격파 기록** (전투 축) → 스토리기획 4.5의 "증표(배지) 수집 진열"이 여기에 흡수됨

즉 **급수·도감·전투·증표가 별도 UI 4개가 아니라 화면 하나**로 끝난다. 1인 개발에서 이게 결정적이다 — 만들 UI가 3개 줄고, 플레이어가 배울 화면도 1개뿐이다.

- NPC 심부름 퀘스트 — **5~8개로 상한.** 텍스트 물량이 1인 개발 예산을 조용히 먹는다.
- 반절표 완성(140/140) 도전과제 + 완성 시 훈민정음 소품 연출.

### 안 함 (판단 완료)

5장 금지 목록 전체 + 아래:

- **필드 전투** — 사이드뷰 12장 결정 유지.
- **창작마당** — 기획초안 21장에 장기 콘텐츠로 언급됐지만, 완성도 5% 시점에서 검토 대상이 아니다.
- **도감 100% = 11,172자** 같은 전체 집합 목표 — 반절표 140칸이 대체한다.
- **급수별 캐릭터 외형 변화** — 아트 물량 대비 효과 없음.

## 7. 외국인 플레이어 체크

| 요소 | 한국어 지식 없이 통하는가 |
|---|---|
| 반절표 도감 | **통한다 — 오히려 최고의 장치.** 격자 자체가 "자음 × 모음 = 글자"를 텍스트 0줄로 설명한다. 외국인 교재 1페이지를 트로피 케이스로 바꾼 것 |
| 자음 사다리 | 통한다. ▒ → 글자 전환은 순수 시각 정보 |
| ▒ 복원 연출 | **통한다.** "내가 뭔가를 고쳤다"가 언어 없이 읽힌다. 오히려 한국인보다 외국인에게 더 강할 수 있다 (해독 불가 → 해독 가능의 체감) |
| 전투 시련 | 통한다. 제한 수는 숫자, 전조는 아이콘화 가능 |
| 특별 서가(희귀 글자) | 통한다. 금색 = 희귀는 글로벌 문법 |
| **위험** | 반절표의 **행 머리 자음 이름**(ㄱ = "기역")을 텍스트로 쓰면 안 됨 → **자모 글리프만** 표시 |
