# 사이드뷰 전환 기획 (메이플식 이동 · 맵 포맷 v2 · 마이그레이션)

2026-07-17 작성. 맵 모드를 **탑다운(WASD 자유 이동) → 메이플스토리식 사이드뷰 플랫포머**로 전환하는 구조·시스템 기획.
아트 스타일·해상도·팔레트는 아트 디렉션 문서 소관 — 이 문서는 **구조, 수치, 데이터 포맷, 마이그레이션**만 다루며 아트와는 "인터페이스"(9장)로만 만난다.

관련 문서: `게임기획초안` 13장(큰 맵 기반 UI), `스토리기획` 2~4.5장(깨진 글자·사천왕), `구현결정로그` D-16/17/22/23.

---

## 0. 핵심 결정 요약

| 항목 | 결정 |
|---|---|
| 이동 문법 | 좌우 걷기/달리기 + 1단 점프 + 사다리. 낙하 데미지 없음 |
| 발판 | 메이플식 원웨이(one-way) 발판 채택: 아래에서 점프로 통과, ↓+점프로 하강 |
| 사다리 | ↑/↓ 승강, 좌우+점프로 이탈 가능. 로프는 도입하지 않음(사다리로 통일) |
| 물리 | Unity 물리(Rigidbody2D) **사용 안 함** — 기존처럼 코드 이동(문자 그리드 AABB 판정) 유지 |
| 데이터 | 기존 terrain 문자열 그리드 유지, 문자 의미만 사이드뷰용으로 재정의(`#`/`=`/`H`/`.`) + `version: 2` |
| 입력 | 점프=Space, **상호작용=↑(기존 Space에서 이관)** — 메이플 포탈 문법 |
| 진행 로직 | MapProgress·자음 게이트·방 보상·출구 required 등 **전부 무변경 재사용** |
| 전환 순서 | 시작의 숲 1개 프로토타입 → 체감 확정 → 나머지 4맵 → 탑다운 코드 제거 |
| 접근성 원칙 | **모든 필수 지점은 점프 없이도(사다리·계단으로) 도달 가능** — 플랫포머 스킬 게임이 아니라 퍼즐 게임의 탐험 허브다 |

> 외국인 플레이어 관점: 메이플식 문법(원웨이 발판, ↓+점프 하강, ↑ 포탈)은 전 세계 플랫포머 공통 관습이라 텍스트 설명 없이 통한다. 이동 튜토리얼은 글이 아니라 **지형 순서**(평지 → 낮은 단차 → 사다리)로 가르친다(7.1장).

## 1. 이동 문법

### 1.1 기준 단위
- **타일 1칸 = 1 유닛(u)**. 발판 충돌 상면 = 칸의 윗변. 캐릭터 위치 기준점 = 발 밑 중앙(pivot bottom-center).
- 캐릭터 충돌 박스: **폭 0.6u × 높이 1.3u** (발 기준 위로).

### 1.2 수치 (초기값 — 프로토타입에서 체감 튜닝 후 확정)

| 항목 | 값 | 비고 |
|---|---|---|
| 걷기 속도 | 6.0 u/s | 기존 탑다운 MoveSpeed와 동일. 가감속 없이 즉시 최고속(반응성 우선) |
| 달리기 속도 (Shift) | 9.5 u/s | 기존 10.5에서 소폭 하향 — 사이드뷰는 화면 가로 시야가 좁아 과속 체감 |
| 중력 | 40 u/s² | |
| 최대 낙하 속도 | 18 u/s | |
| 점프 초속(수직) | 14.5 u/s | → 최고점 **약 2.6u**, 체공 약 0.73초 |
| 점프 수평 사거리 | 걷기 약 4.3u / 달리기 약 6.9u | 같은 높이 착지 기준 |
| 사다리 승강 속도 | 4.0 u/s | 한 층(4u)을 1초에 |
| 공중 좌우 제어 | 지상과 동일(100%) | 메이플식 |

**지형 설계 상수** (수치의 근거이자 레벨 규칙):
- 표준 층 간격(발판 상면 간): **4u** → 점프(2.6u)로 못 오름, **사다리로만** 층 이동.
- 낮은 단차: **2u** → 점프로 오름 (계단·언덕용).
- 필수 경로의 간극(구덩이) 최대 폭: **3u** (걷기 점프 4.3u에 여유). **달리기 점프를 요구하는 필수 경로 금지.** 보너스 지름길은 5.5u까지 허용.

### 1.3 점프
- **1단 점프만.** 2단 점프·벽점프·대시는 없고 앞으로도 이동 스킬 해금 계획 없음(맵이 스킬 점프를 요구하지 않게 하기 위한 의도적 제한).
- **가변 점프**: 상승 중 점프 키를 떼면 수직 속도 ×0.5 (짧은 점프).
- **코요테 타임 0.08초**: 발판 끝에서 떨어진 직후에도 점프 허용.
- **점프 버퍼 0.12초**: 착지 직전 입력을 착지 시 발동.
- 낙하 데미지 **없음**. 지형 위험 요소(가시 등) 없음 — 탐험에 실패 페널티를 두지 않는다.

### 1.4 발판 통과 규칙 (원웨이)
- `=` 원웨이 발판: **하강 중일 때만** 상면에서 충돌(착지). 상승 중엔 통과, 수평 이동도 자유.
- **↓ + 점프**: 딛고 있는 원웨이 발판을 뚫고 하강 (해당 발판과의 충돌을 0.25초 무시).
- `#` 솔리드: 전방향 충돌. 하강 통과 불가. 지면·벽·천장용.

### 1.5 사다리 (상태 기계)

상태: `Grounded`(접지) / `Airborne`(공중) / `OnLadder`(사다리).

| 전이 | 조건 | 처리 |
|---|---|---|
| →OnLadder (아래에서) | 캐릭터 중심 x가 사다리 열 중심 ±0.4u & ↑ 입력 & 몸이 `H` 칸과 겹침 | x를 사다리 중심에 스냅, 속도 0 |
| →OnLadder (위에서) | 발 밑 칸이 사다리 꼭대기(2.2장) & ↓ 입력 | 동일 |
| OnLadder 중 | ↑/↓로 4.0 u/s 승강. 좌우 입력 무시, 중력 없음, 상호작용 비활성 | |
| →Grounded (꼭대기) | 머리 위에 `H` 없음 & 위 칸이 설 수 있는 칸 | 자동으로 올라서기(스텝업) |
| →Grounded (바닥) | 발이 지면 접촉 | |
| →Airborne (점프 이탈) | **점프 + 좌/우 동시 입력** (점프 단독은 무시 — 오조작 방지) | 수평 3.0 u/s + 수직 8.7 u/s(점프 초속의 60%)로 이탈 |

### 1.6 입력 매핑 (변경점 주의)

| 키 | 동작 |
|---|---|
| ←/→, A/D | 좌우 이동 |
| Shift | 달리기 |
| **Space** (보조: Alt) | **점프** |
| **↑ / W** | **상호작용**(스팟·출구·상점·보스) + 사다리 오르기 |
| ↓ / S | 사다리 내려가기, ↓+Space = 원웨이 하강 |

- **기존 "Space=상호작용"이 "↑=상호작용"으로 이관된다.** HUD 힌트 문구(`MapWorld.Input.UpdateHint`)의 "Space: ..." 표기를 전부 "↑: ..."로 교체.
- ↑의 사다리/상호작용 중의성은 **배치 규칙으로 차단**: 스팟·출구 칸과 그 좌우 1칸에는 사다리를 두지 않는다(로더 검증, 3.4장).

## 2. 물리 구현 방침: 코드 이동 유지 (Unity 물리 비사용)

**권장: 기존처럼 순수 코드 캐릭터 컨트롤러.** 근거:

1. 현 씬은 전부 절차 생성이고 콜라이더가 하나도 없다 — Rigidbody2D 도입은 씬 구축·튜닝 비용만 추가.
2. 충돌 대상이 문자 그리드뿐이라 판정이 결정론적이고 단순하다: **축분리 스윕**(수평 이동 → 충돌 해소 → 수직 이동 → 충돌 해소). 기존 `CanStand`의 축분리 철학 그대로.
3. 원웨이 발판·사다리·↓점프 하강은 Unity 물리로 하면 PlatformEffector2D 등 예외 처리가 늘고, 코드 판정으로 하면 각각 if 한 줄 수준.
4. 이동 로직을 순수 C#으로 두면 EditMode 테스트 가능(프로젝트 원칙: 엔진 코드는 MonoBehaviour와 분리).

컨트롤러 판정 의사코드:

```
매 프레임:
  vx = 입력 × 속도, vy += -중력 × dt (OnLadder면 vy = 입력 × 4)
  x 이동 → 몸 박스가 겹친 '#' 열에서 밀어내기
  y 이동 → 하강 중: 발이 '#' 상면 또는 '=' 상면(직전 프레임에 위였을 때만)을 통과하면 착지
           상승 중: 머리가 '#' 하면에 닿으면 vy=0
  접지 갱신 → 코요테 타이머, 점프 버퍼 처리
```

## 3. 맵 데이터 포맷 v2

### 3.1 스키마

기존 `MapJson` 구조를 **그대로 유지**하고, `terrain` 문자 의미 재정의 + `version` 필드만 추가한다.

```json
{
  "id": 1,
  "version": 2,
  "title": "시작의 숲",
  "theme": "기초 배우기",
  "bgm": "bgm_forest",
  "terrain": [
    "..............................",
    "..............H...............",
    "......===.....H....==.........",
    "..............H...............",
    "##############################"
  ],
  "spawn": [1, 3],
  "tutorialStages": [61, 62],
  "spots":  [{ "stage": 61, "pos": [6, 3] }],
  "exits":  [{ "pos": [28, 3], "toMap": 2, "arrive": [2, 12], "label": "시작의 마을", "required": 8 }],
  "shop":   [17, 3],
  "boss":   { "pos": [24, 3], "config": "boss_crossword" },
  "rooms":  [{ "stages": [61, 62], "reward": "ㄹ", "label": "시작의 숲" }]
}
```

- `version` 생략 시 **1(탑다운)로 간주** — 한 맵씩 이전하는 공존 전략의 스위치(10장).
- 좌표 규약은 기존과 동일: JSON은 위에서부터 행 번호, 로더 `P()`가 y 뒤집기. `arrive`는 목적지 맵 좌표(`ResolveArrive`) — **전부 재사용**.

### 3.2 terrain 문자 정의 (v2)

| 문자 | 의미 | 충돌 |
|---|---|---|
| `.` | 공기 | 없음 |
| `#` | 솔리드 (지면·벽·천장) | 전방향 |
| `=` | 원웨이 발판 | 상면만, 하강 중만 |
| `H` | 사다리 | 없음(통과). ↑/↓로 부착 |

- **사다리 꼭대기 규칙**: `H` 칸의 좌 또는 우가 `=`/`#`이면 그 `H` 칸 자체를 원웨이 발판으로 취급한다(발판을 사다리가 관통하는 메이플 구조를 한 문자로 표현). 그 위에 설 수 있고, ↓로 사다리 재진입.
- 장식(나무·간판·배경)은 terrain에 넣지 않는다 — 아트 레이어 소관(9장). v1의 `~`(물), `-`(길), `@`(바위)는 v2에서 폐기.

### 3.3 배치 규약
- `spawn`/`spots`/`exits`/`shop`/`boss`의 `pos` = **오브젝트가 서 있는 발 칸**. 그 칸은 `.` 또는 사다리 꼭대기 `H`, 바로 아래 행은 `#`/`=`/사다리 꼭대기여야 유효.
- 스팟·출구·상점·보스 칸과 그 좌우 1칸에 `H` 금지 (↑ 입력 중의성 차단).
- 스팟 간 수평 간격 최소 4u (상호작용 판정·힌트 겹침 방지).

### 3.4 로더 검증 (신규, EditMode 테스트 대상)
1. 모든 `pos`가 3.3 배치 규약을 만족하는가.
2. 모든 사다리 기둥(`H` 수직 연속)의 꼭대기가 설 수 있는 칸으로 끝나는가.
3. `arrive`가 목적지 맵(v2)에서 설 수 있는 칸인가 — **맵 간 연결 정합 자동 검사** (마이그레이션 리스크 1번의 안전망).
4. spawn에서 모든 스팟·출구까지 도달 가능한가 — 걷기+사다리만으로(점프 불사용) 그리드 BFS. **점프 없이 도달 불가한 필수 지점은 로드 에러.**

### 3.5 상호작용 판정 (탑다운 반경 → 사이드뷰 박스)
- 기존 `InteractRadius 0.65`(원형) → **박스 판정: 수평 ±0.8u, 수직 ±1.2u** (스팟 발 칸 기준). 같은 발판 위에서만 반응하고 위·아래 층의 스팟에는 반응하지 않게 하는 것이 목적.

### 3.6 마이그레이션 난이도 평가

| 대상 | 재사용률 | 작업 |
|---|---|---|
| `MapData.cs` (JSON 파싱·좌표 변환) | 높음 | `version` 필드 + `Walkable` → v2 충돌 질의로 교체, 검증 4종 추가 |
| `MapProgress`, `ProgressStore`, 자음 게이트(D-22), 방 보상(D-23) | **100%** | 무변경 |
| `MapWorld.cs` (상태·RefreshStates·HUD) | 약 90% | 스팟 상태 색·▒·HUD 로직 그대로 |
| `MapWorld.Input.cs` (이동) | 0% | 신규 작성 (사이드뷰 컨트롤러, 1~2장 명세대로) |
| `MapWorld.Build.cs` (지형 렌더) | 낮음 | v2 문자 → 스프라이트 매핑 재작성. 폴백(절차 생성 색 블록) 패턴은 유지 |
| `GameApp.cs` | 높음 | `version`에 따라 MapWorld/SideWorld 생성 분기 1곳 |
| 맵 JSON 5개 | 구조 100% / 좌표 0% | terrain 전면 재작성 + pos 재배치. **stage id, rooms 묶음·보상, exits 연결·required는 그대로 복사** |
| 세이브 | 높음 | 별·자음·골드는 스테이지 id 기반이라 무영향. 단 `last_map` 복귀 좌표는 맵이 v2로 바뀐 경우 무효 → **spawn으로 복귀** 규칙 추가 |

종합: **중(中).** 이동·렌더는 신규지만 명세가 단순하고, 진행 로직·데이터 구조·연결 그래프는 손대지 않는다.

## 4. 퍼즐 스팟 · 출구 · 상점 · 보스 상호작용

### 4.1 스팟 진입 UX
- **근접 + ↑** (1.6장). 판정은 3.5장 박스.
- 스팟 비주얼 = 발판 위에 세워진 구조물(팻말/석등/문 — 실루엣은 아트 소관, 시스템 인터페이스: **바닥 앵커 1칸, 표시 영역 1×1~1×2u**). 현재의 "글자 라벨(목표 첫 글자) + 상태색" 시스템은 그대로: 잠김(회색)/열림(종이색)/다음 튜토리얼(주황)/클리어(금색).
- 근접 시: 스팟 위에 **↑ 화살표 아이콘** 표시(언어 무관 — 외국인 대응) + 기존 하단 HUD 힌트 텍스트 유지.

### 4.2 자음 게이트 ▒ (D-22)
- 로직 무변경: 미회수 자음 스테이지는 라벨 `▒` + 어두운 색, 진입 시 실패음 + "필요한 자음" 힌트.
- 사이드뷰 연출(아트 요청 사항): 게이트 스팟은 "먹 안개에 잠긴 문" 톤 — 시스템 스펙은 색·라벨 교체뿐이고 이펙트는 아트 소관.
- 배치 원칙: ▒ 스팟은 **시야에는 들어오되 필수 동선 밖**(지붕 위, 막다른 발판)에 둔다 — "나중에 돌아올 곳"이 한눈에 보이는 것이 사이드뷰의 장점.

### 4.3 방 보상 (D-23)
- 로직 무변경(맵 복귀 시점에 자음 회수 팝업). 사이드뷰에서 방(room)은 **층 또는 구간**과 일치시킨다(7장) — "이 층을 다 깨면 자음 하나"가 공간적으로 읽히게.

### 4.4 출구 (맵 간 이동)
- 로직 무변경(`required` 클리어 수로 개방, 양방향 D-17).
- 배치 문법 3종: **좌우 끝 경계**(걸어 나가는 이웃 맵 — 예: 숲→마을), **문/대문 구조물**(↑로 진입 — 예: 마을→사찰 산문), 어느 쪽이든 상호작용은 동일하게 ↑ + 페이드 전환.
- 잠긴 출구는 기존대로 `X` + "이 지역 n/m 클리어" 힌트.

### 4.5 상점·보스
- 상점: 지상층 점포 구조물, ↑로 개방(로직 무변경).
- 보스(사천왕): **맵 지형의 정점**(최상층 또는 맨 끝)에 배치 — "정상 결전" 문법으로 통일(7장). 미격파 붉은색/격파 금색 상태 표현 유지. 전투는 기존대로 별도 화면 전환(필드 전투 아님, 12장).

## 5. 카메라

- `orthographicSize = 5` 유지 → 세로 시야 10u = 표준 층(4u) 기준 **2.5개 층**이 한 화면에.
- **수평**: 플레이어 x를 스무딩 0.1초로 추적. (룩어헤드는 MVP 이후 옵션.)
- **수직 데드존**: 카메라 목표 y = **기준 y**(마지막 접지 y; 사다리 중에는 현재 y). 점프 중에는 y를 따라가지 않는다(화면 출렁임 방지). 예외 — 낙하로 플레이어가 화면 하단 25% 아래로 내려가면 기준 y를 즉시 현재 y로 갱신.
- **맵 경계 클램프**: 기존 `SnapCamera` 로직 그대로(halfW/halfH 클램프, 맵이 화면보다 작은 축은 중앙 고정).
- 수직 이동이 많은 자모 사찰(7.4장)이 데드존 튜닝의 기준 맵.

## 7. 기존 맵 5개의 사이드뷰 재해석

공통 원칙 — **맵마다 "지형 리듬"이 곧 개성이다** (엘리니아 모델: 같은 권역 문법 안에서 맵별 변주):

| 맵 | 지형 리듬 | 고유 기믹 |
|---|---|---|
| 시작의 숲 | 평탄한 수평 개활지 | 없음 — 이동 문법 학습이 기믹 |
| 시작의 마을 | 3단 테라스 허브 | 4방향 출구 분기 |
| 받침 고개 | 사선 상승 스위치백 | 낙하 지름길 (내려올 땐 한 번에) |
| 자모 사찰 | 수직 탑 | 사다리 릴레이 |
| 낱말 저잣거리 | 초장거리 수평 번화가 | 지붕 위 원웨이 고속도로 |

스팟 배치 원칙(전 맵 공통):
1. 튜토리얼 스팟은 스폰에서 **좌→우(또는 아래→위) 단조 진행** 순서 = `tutorialStages` 순서와 일치 (강제 순서인데 동선이 왕복하면 안 됨).
2. 방(room) 묶음 = 층/구간과 일치.
3. ▒ 게이트 스팟은 동선 밖 + 시야 안.
4. 보스는 지형 정점.
5. 모든 스팟은 걷기+사다리만으로 도달 가능(3.4장 BFS 검증).

### 7.1 시작의 숲 (map_01) — "평지 숲길" · 이동 튜토리얼
- **규모: 가로 60u × 1.5층** (지상 + 낮은 언덕/나무 발판).
- 구간 설계가 곧 튜토리얼: ①x0~20 완전 평지(걷기·달리기) → ②x20~40 2u 단차 언덕 2개(점프) → ③x40~52 첫 사다리 + 4u 나무 발판 1개(사다리, 스팟 68이 그 위) → ④x52~60 출구.
- 스팟 61~68을 x=6부터 약 6u 간격 일렬 배치(68만 사다리 위) — 퍼즐 튜토리얼 순서와 이동 튜토리얼 순서가 겹쳐 흐른다.
- 출구(→마을, required 8) = 오른쪽 끝 경계.

```
                                  ==68==
                                    H
        __/¯¯\__/¯¯\_______________ H ___________
  P  61   62  63  64  65  66  67    H         → 출구
#################################################
```

### 7.2 시작의 마을 (map_02) — "3단 테라스 허브"
- **규모: 가로 80u × 3층.**
- 지상(길): 스폰(좌), 상점(중앙), 스팟 1~5 (방A → ㅁ). 왼쪽 끝 경계 = 숲 출구(required 0), 오른쪽 끝 경계 = 저잣거리 출구(required 8).
- 2층(기와 테라스): 스팟 6~10 (방B → ㅂ), 오른쪽 2층 끝에 고갯길 대문 = 받침 고개 출구(required 3).
- 3층(망루): 스팟 69~72 + 보스 crossword(정점), 3층 중앙 종루 문 = 자모 사찰 출구(required 5).
- 허브의 문법: **위로 올라갈수록 후반 콘텐츠** — required가 큰 출구일수록 높은 곳에 있어 "성장하면 위로 간다"가 공간으로 읽힌다.

```
   [사찰 문]   69 70 71 72  [보스王]      ← 3층 망루
  ======H=====================
     6  7  H  8  9  10        [고개 대문] ← 2층 기와
  =========H====================H=====
숲← P  1  2  3  [상점] 4  5     H   →저잣거리
######################################
```

### 7.3 받침 고개 (map_03) — "스위치백 오르막 산길"
- **규모: 가로 70u × 5층** (왼쪽 아래 → 오른쪽 위로 지그재그 상승).
- 층당 스팟 2~3개: 1층 11·12(튜토리얼)·13, 2층 14·15, 3층 16·17, 4층 18·19, 정상 고갯마루 = 보스 boss_batchim(받침 사범). 73~77은 각 층의 옆가지 발판(▒ 후보 포함).
- 테마 일치 연출(아트 요청): "받침이 글자를 아래서 받치듯, 발판이 위층을 받친다" — 층을 받치는 기둥·석축 실루엣.
- 고유 기믹: 각 층 끝에서 **아래층으로 뛰어내리는 낙하 지름길**(낙뎀 없음) — 올라갈 땐 순서대로, 내려올 땐 한 번에. 왼쪽 끝 1층 = 마을 출구.

### 7.4 자모 사찰 (map_04) — "수직 탑" · 사다리 중심
- **규모: 가로 36u × 7층** — 가장 좁고 가장 높은 맵. 카메라 수직 데드존의 기준 맵.
- 하부 1~3층 = 바깥마당: 20·21(튜토리얼)·23·24 (방1 → ㅈ). 상부 4~6층 = 안마당: 22·25·26 (방2 → ㅊ). 최상층 법당 = 보스 boss_jamo(겹자모 노승). 78~83은 층 사이 옆가지.
- 사다리 릴레이: 층마다 사다리가 좌/우로 번갈아 배치되어 오르는 동선이 S자 — 단조로운 수직 이동 방지. 층 하나는 사다리 대신 2u 계단 2개로 변주.
- 1층 산문(대문) = 마을 출구.
- "방을 깰수록 탑을 오른다" — 자음 회수(ㅈ→ㅊ→보스 ㅋ)가 고도와 일치하는 유일한 맵.

### 7.5 낱말 저잣거리 (map_05) — "초장거리 번화가"
- **규모: 가로 110u × 2층+지붕** — 가장 긴 맵. 달리기(9.5 u/s)로 편도 약 12초.
- 지상(장터길): 점포가 늘어서고 처마 아래마다 스팟 — 27~34(장터 초입, 방→ㅌ), 35~42(장터 안쪽, 방→ㅍ). 왼쪽 끝 = 마을 출구.
- 2층(처마·누각): 43~54.
- 지붕 위(원웨이 고속도로): 84~93 보너스 스테이지(▒ 게이트 다수) — 지붕 발판을 연속으로 뛰는 **귀환 지름길**을 겸한다. 110u 왕복 피로의 해법.
- 오른쪽 끝 대형 상단(商團) 누각 = 보스 boss_word(낱말 장사꾼). 상점은 이 맵이 아니라 마을에 있으므로 무변경.

## 8. 권역 통일성 + 맵별 개성 (시스템 담당분)

- **통일성(시스템)**: 전 맵 공통 — 문자 4종의 충돌 문법, 층 간격 4u, 스팟 팻말·↑ 아이콘·상태색, HUD, 출구 문법 3종. 플레이어가 어느 맵에서든 "읽는 법"이 같아야 한다.
- **개성(시스템)**: 7장의 지형 리듬 + 맵당 고유 기믹 1개. **색·소품·배경 모티프의 변주는 아트 디렉션 문서 소관** — 이 문서는 각 맵의 리듬 지문만 확정한다.
- MVP 이후: 움직이는 발판, 지형이 변하는 "맵 거대 퍼즐"(스토리기획 3장), 숨겨진 보물의 점프 챌린지 배치.

## 10. 단계별 전환 계획

`version` 필드가 공존 스위치다: v1 맵은 기존 `MapWorld`, v2 맵은 신규 `SideWorld`(가칭)로 `GameApp.StartMap`에서 분기 → **한 맵씩 이전하고 언제든 되돌릴 수 있다.**

1. **0단계 — 포맷·검증**: MapData에 version+v2 충돌 질의+로더 검증 4종(3.4장) → 검증: EditMode 테스트(정상/위반 맵 픽스처).
2. **1단계 — 컨트롤러 프로토**: SideWorld에 이동·점프·사다리·원웨이(1~2장 수치) + 절차 생성 색 블록 렌더 → 검증: 테스트 맵에서 상태 전이 전 항목 수동 체크리스트(코요테, 버퍼, ↓점프, 사다리 이탈, 스텝업).
3. **2단계 — 프로토타입 맵**: map_01을 v2로 재작성(7.1장), 상호작용·HUD·카메라 이식 → 검증: 숲에서 튜토리얼 8스팟→방 보상(ㄹ)→출구까지 전체 루프 + **이동 체감 사용자 판정(수치 확정 게이트)**.
4. **3단계 — 전 맵 확장**: map_02(허브·출구 4개 정합) → 03 → 04(카메라 수직 튜닝) → 05 순. 한 맵 끝날 때마다 arrive 검증 통과 + 인접 맵 왕복 확인.
5. **4단계 — 탑다운 제거**: 5맵 전부 v2 + 사용자 확인 후 MapWorld(구) 3파일과 v1 분기·v1 문자 정의 삭제, `last_map` 복귀 좌표 규칙 정리.

각 단계는 커밋 단위로 분리. 2단계 완료 전에는 3단계 데이터 작업을 시작하지 않는다(수치가 바뀌면 배치가 전부 흔들린다).

## 12. 비범위 (이번 전환에서 하지 않는 것)

- **몬스터 필드 배치·플랫포머 전투** — 전투(사천왕)는 기존 별도 화면 전환 유지.
- **NPC 배치·대화·심부름 퀘스트** (스토리기획 4.5) — 별도 건.
- **로프**, 2단 점프, 벽점프, 대시, 이동 스킬 해금 — 사다리 하나로 통일.
- 낙하 데미지, 가시·용암 등 지형 위험.
- 움직이는 발판, 지형 변형(맵 거대 퍼즐) — MVP 이후.
- 미니맵·월드맵 UI.
- 패럴랙스 내용물·오토타일링·타일 해상도 — 아트 디렉션 문서 소관.
- 퍼즐 규칙·스테이지 데이터 — 전혀 손대지 않음 (맵 모드만의 개편).

## 13. 외국인 플레이어 체크

- 이동 문법 학습에 텍스트 0줄: 숲의 지형 순서(평지→단차→사다리)가 가르친다.
- 메이플식 관습(원웨이, ↓+점프, ↑ 포탈)은 글로벌 플랫포머 공통 문법.
- 상호작용 유도는 ↑ 화살표 아이콘(비언어) + HUD 텍스트(로컬라이즈 대상)의 이중화.
- ▒ 게이트·클리어 금색 등 상태는 전부 색+아이콘으로 판독 가능 — 한국어 몰라도 "잠김/열림/다음/완료"가 읽힌다.

## 14. 승인 및 수정 지시 (2026-07-17 승인 보드 결정)

**승인됨** — 단, 아래 수정 지시를 프로토타입에 반영한다 (사용자 코멘트 원문 기준):

1. **사다리 오르내리기 = W/S** (↑↓ 방향키 병행).
2. **점프 = Space** (기획서와 동일).
3. **2단 점프 = 상점 구매 아이템** — ItemStore에 이동 능력 아이템 카테고리 신설. 기본은 1단 점프.
4. **Unity 물리 우선 시도** — 기획서의 코드 이동 권장을 뒤집어 Rigidbody2D 기반 컨트롤러로 프로토타입 ("그게 더 자연스러우니까"). one-way 발판은 PlatformEffector2D, 사다리는 트리거 존+중력 해제. 체감이 부자연스러우면 코드 이동 폴백 (프로토타입 게이트에서 판정).
5. **레이어 구조** — 메이플처럼 맨 앞 레이어에서 플레이하고, 뒤에 배경 레이어(패럴랙스)를 쌓는 구조를 맵 포맷에 반영: `layers: [{type: playfield|backdrop, ...}]`.
6. **맵 확장 대비** — 사용자가 후속 작업으로 맵 확장을 계획 중임을 명시. 포맷은 신규 지역·대형 맵 추가가 스키마 변경 없이 가능하도록 유지.
