# 구현 결정 로그

밤샘 자율 구현 중 내린 결정들. 명세에 없는 세부사항의 해석과 이유를 기록한다.

## 1단계: 규칙 엔진

### D-01. 타일 = char 하나
모든 타일(자모/글자)을 char 하나로 표현. 자모는 호환 자모(U+3131~), 글자는 완성 음절(U+AC00~).
**이유**: 표준 조합쌍 원칙(명세 3장) 덕분에 조합 구조가 문자에서 유일하게 유도되므로 별도 이력/객체가 불필요. 상태 인코딩·솔버·undo가 전부 단순해짐.

### D-02. 좌표계 = x 오른쪽+, y 위쪽+
Unity 월드 좌표와 일치시켜 표현 계층 변환 오류를 줄임. 스테이지 텍스트(행 배열)는 위→아래 순서로 쓰고 로더가 y를 뒤집음.

### D-03. 겹받침/쌍자음을 품은 글자의 잠김
명세 5장 "d축 조합이 전혀 없으면 이동"을 조합 트리 전체 재귀로 해석. 예: 꼬(ㄲ+ㅗ)는 ㄲ 내부가 가로 조합이므로 가로 잠김. 결과적으로 "조합이 쌓일수록 무거워진다" 원리가 쌍자음/겹받침에도 일관 적용됨.

### D-04. ㄻ을 모음 쪽으로 밀면 분해+연쇄
ㄻ→ㅏ 밀기: ㄻ+ㅏ 직접 합성은 초성 제약으로 불가하지만, 판정 2단계(분해)가 적용되어 ㅁ이 나가며 ㅁ+ㅏ=마 연쇄가 일어남 (ㄹ|마). 명세의 판정 순서를 그대로 따른 창발적 결과로, 막지 않기로 함.

### D-05. 2별 기본 공식
명세는 3별(최소수+max(1,10%))과 루비만 정의. 2별 기본값을 `최소수 + max(2, round(최소수*0.3))`, 1별은 클리어 자체로 정함. 스테이지 데이터로 개별 조정 가능.

### D-06. 솔버의 수집 행동 축약
같은 문자의 미수집 슬롯들은 서로 교환 가능하므로, 솔버는 "첫 번째 일치 빈 슬롯"에만 수집하는 것으로 분기를 축약 (상태 폭발 방지, 최소 수에 영향 없음).

### D-07. 솔버 상태 상한
기본 2,000,000 상태에서 탐색 중단(Aborted). 중단은 "풀이 불가 확정"이 아니므로 스테이지 검증 시 중단이 나오면 스테이지를 단순화해야 함.

### D-09. [발견된 모순] 명세 5장 판정 순서 vs 요약 표
명세 5장의 번호 규칙은 "1.합성 → 2.분해" 순서인데, 같은 장의 "타일별 밀기 결과 표"는 겉조합 축 밀기를 무조건 "분해"로 서술함. **도착지 타일과 전체 합성이 가능한 경우** 두 서술이 충돌:
- ㄲ→ㅏ: 합성 우선이면 '까', 분해 우선이면 ㄱ|가
- ㅔ←ㅜ: 합성 우선이면 'ㅞ', 분해 우선이면 ㅝ 경유
- 고↓ㄴ: 합성 우선이면 '곤', 분해 우선이면 실패
- 과↓ㄱ: 합성 우선이면 '곽', 분해 우선이면 실패

**해석**: 번호 판정 순서가 명시적 규칙이고 표는 요약이므로 **합성 우선**으로 구현. 근거: 이 순서는 대화에서 직접 확정된 것("밀기 판정 순서" 4단계)이고, 합성 우선이 아니면 받침 글자(곤·곽 류)를 밀기로 만들 방법이 사라져 퍼즐 표현력이 크게 줄어듦. 4개 케이스를 테스트로 고정함. **아침에 명세 표에 각주 추가 여부 확인 필요.**

### D-10. 리뷰 반영 (unity-code-reviewer)
- DecomposeSyllable 비음절 입력 가드, AllSlots/FromRows null·빈 입력 가드
- GameSession의 죽은 코드(EncodeState/LoadState) 제거 — 솔버는 자체 인코딩 사용
- Q/E 필터를 non-alloc 버퍼 방식으로 변경 (UI는 행동 이벤트 시에만 재계산)
- ComposeSyllable 등의 IndexOf 선형 탐색을 Dictionary 캐시로 교체 (솔버 핫패스)
- RuleFlags 구조체 자리 확보 (명세 11장 — MVP 기본값, 동작 불변)
- 솔버 기본 상태 상한 2M → 500k (메모리), BeatDeclaredMin 검증 신호 추가
- 1별 기준(t[0])은 코드에서 미사용임을 주석으로 명시 (1별=클리어, D-05)

### D-08. undo = 전체 스냅샷
보드가 최대 4x4로 작아서 행동마다 전체 상태를 스택에 저장. 커맨드 역연산 방식보다 단순하고 버그 여지가 없음.
