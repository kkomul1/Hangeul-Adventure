### 보류 후보 (임베딩 조항 불명확)
- **EBS 훈민정음 새론체** (EBS): 해례본 기반을 현대화한 서체로 주제 적합성은 높고 "매체·용도 제한 없이 상업적 사용 가능"이라 명시되어 있으나, 라이선스 안내에 **임베딩 조항이 없다**. 수정·재배포 금지 조항만 있음. 쓰려면 EBS에 게임 임베딩 가능 여부 서면 확인 필요 → 후순위.

### 추천 (1순위와 조합)
- **1순위: 상주해례본체** — 타이틀 로고·챕터 제목. "훈민정음 해례본을 복원하는 게임"의 타이틀을 실제 해례본 서체로 쓴다는 것 자체가 아트 디렉션이자 마케팅 포인트다. 눈누 라이선스 표에서 임베딩 허용이 확인된다.
- **보조: 정묵바위체** — 사천왕 이름·보스 연출 등 "힘"이 필요한 장면. 판본체(상주해례본체)와 서예 붓글씨(정묵바위체)의 역할 분담이 명확해 스타일 충돌이 없다.
- **안전판: 나눔손글씨 붓 또는 연성체(OFL)** — 위 두 서체의 배포처가 라이선스를 개정하거나 문의 회신이 애매할 경우의 OFL 대체재.

## 2. 옛한글 조합 지원 폰트 (엔딩 훈민정음 서문)

### 기술 배경: 왜 일반 폰트로는 깨지는가
- "나랏말ᄊᆞ미"의 `ᄊᆞ`는 완성형 음절 코드포인트가 **존재하지 않는다**. 유니코드 옛한글은 첫가끝(초성 U+1100대 + 중성 U+119E(ㆍ) 등 + 종성) **조합형 자모 나열**로만 표현되고, 폰트의 OpenType GSUB 기능(ljmo/vjmo/tjmo)이 이를 하나의 음절 모양으로 합쳐(셰이핑) 그린다.
- **Unity TMP(uGUI)는 GSUB 셰이핑 엔진이 없다.** 동적 아틀라스 여부와 무관하게, 옛한글 지원 폰트를 넣어도 자모가 `ᄉᄉᆞ`처럼 옆으로 나열되어 깨진다.
- 우회로 1 — **한양PUA**: 함초롬 LVT·나눔 옛한글 계열은 옛한글 음절을 사설영역(PUA) **완성형 글리프**로도 수록한다. 서문 텍스트를 한양PUA 코드로 변환해 두면(변환 도구: 한컴오피스, 날개셋 입력기 등) TMP에서도 글리프 단위로 정상 렌더링된다. 표준이 아니고 검색·복사에 부적합하지만 엔딩 연출 한정이므로 문제없다.
- 우회로 2 — **Unity 6 UI Toolkit ATG(Advanced Text Generator)**: HarfBuzz 기반 셰이핑을 지원한다(Unity 6.0 옵트인, 6.5부터 UITK 기본). 엔딩 화면만 UITK + ATG로 만들면 첫가끝 원문을 그대로 쓸 가능성이 있다 — 단, 한국어 옛한글 셰이핑이 실제로 되는지는 **직접 검증 필요**.
- 우회로 3 — **프리렌더 이미지**: 서문을 외부 도구에서 렌더링해 스프라이트로 넣는다. 가장 확실하고 MVP에 적합. 이 경우 폰트를 빌드에 임베딩하지 않으므로 라이선스 부담도 가장 작다(단, 결과물 사용 허용은 여전히 필요).
- 참고: Unity ATG 문서 https://docs.unity3d.com/6000.3/Documentation/Manual/UIE-advanced-text-generator.html

### 함초롬체 라이선스 검증 결과 — "애매함"으로 보고
한컴 공식 사이트에서 라이선스 원문(EULA) 페이지를 직접 확보하지 못했다(다운로드 센터에는 라이선스 문구 없음). 2차 출처(위키백과·나무위키·타입피디아 등)에 인용된 조항은 다음과 같다:
- "개인 및 기업 사용자에게 무료로 제공되며, 모든 출판물과 저작물에서 **임베딩을 포함해** 자유롭게 사용 가능"
- 동시에 "**상업적인 목적으로 배포 및 수정은 불가**"
- 문제: 상업 게임 빌드에 폰트 파일을 포함해 판매하는 행위가 앞 조항의 '임베딩'인지, 뒤 조항의 '상업적 배포'인지 **해석이 갈린다.** '출판물·저작물'이 게임을 포함하는지도 원문 확인 전에는 단정할 수 없다.
- 함초롬 LVT는 KTUG 커뮤니티가 GSUB/GPOS를 보강해 **수정·재배포한 파생본**이라 원본 EULA의 수정·배포 조항과의 관계가 한 겹 더 복잡하다.
- **결론: 상업 게임 임베딩용으로는 리스크가 있어 후순위. 쓰려면 한글과컴퓨터에 서면 문의 필요.** (참고: 위키백과 https://ko.wikipedia.org/wiki/함초롬체 , KTUG https://www.ktug.org)

### 추천 (기술 경로별)
- **1순위: 나눔명조 옛한글** — 이 프로젝트의 현 스택(TMP)에서 실제로 렌더링 가능한 유일한 현실적 경로다. 서문을 한양PUA로 변환 → TMP 정적 폰트 에셋에 해당 글리프 베이크 → 엔딩 화면에서 사용. 명조 계열이라 "복원된 해례본" 연출 톤과도 맞는다. 다운로드 시 동봉 라이선스에서 OFL 고지 확인이 확정 조건.
- **2순위: 본명조(OFL)** — 라이선스는 가장 깨끗하지만 PUA가 없어 TMP로는 못 쓴다. 엔딩을 UITK ATG로 만들거나 서문을 프리렌더 이미지로 처리하는 경우의 선택지.
- **MVP 권고**: 엔딩 서문은 **프리렌더 이미지 + 현대어/영문 자막(일반 UI 폰트)** 조합이 가장 저위험·저비용. 폰트 임베딩 검증은 그 다음 단계로 미뤄도 된다.

### 검증 체크리스트 (구현 전 필수)
1. [ ] 나눔명조 옛한글 다운로드본에 한양PUA 글리프 존재 확인 + 동봉 라이선스 OFL 여부 확인
2. [ ] 서문 텍스트 첫가끝 → 한양PUA 변환본 제작, TMP 정적 아틀라스에 베이크 후 렌더 테스트
3. [ ] (선택) Unity 6 UITK ATG에서 첫가끝 원문 셰이핑 테스트 (본명조로)
4. [ ] 실패 시 프리렌더 이미지 경로로 확정

## 3. 라이선스 공통 주의사항
1. **"눈누 등재 = 안전" 아님**: 눈누는 요약일 뿐이다. 반드시 배포처 원문을 확인하고, 폰트 파일과 라이선스 전문을 `Assets/Art/Fonts/<폰트명>/`에 함께 커밋한다.
2. **OFL이 아닌 무료 폰트의 공통 조항**: 폰트 파일 수정 금지·유료 재판매 금지. TMP SDF 아틀라스 생성은 폰트 파일 수정이 아니라 렌더링 산출물이므로 일반적 해석상 문제없으나, 빌드에 **원본 ttf/otf를 동적 폰트로 포함**하는 경우가 '임베딩' 조항의 적용 대상이다.
3. **OFL 폰트 사용 시 의무**: 라이선스 전문(카피라이트 고지 포함)을 게임 크레딧 또는 동봉 문서에 포함해야 한다. 폰트 이름을 바꿔 재배포하지 않는 한 자유롭게 임베딩·판매 가능.
4. **공공기관 서체 리스크**: 지자체·공공기관 서체는 담당 부서 개편 시 라이선스 페이지가 사라지는 일이 잦다. 다운로드 시점의 라이선스 페이지를 **스크린샷/PDF로 보관**할 것.
5. 출처 표기는 의무가 아니어도 크레딧에 전 폰트 출처를 기재한다 (상주시청, 상상토끼, 네이버, 우아한형제들 등).
